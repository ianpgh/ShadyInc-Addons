# Shady Remote Publisher v1.2.1

Installable iPhone publisher for WoW Forever addon ZIPs. This service runs independently of the Windows PC. The production repository and GitHub Pages website retain their existing structure. The deployment branch can be deployed directly without merging into `main`.

## Setup from an iPhone

1. In Safari, open the [Render dashboard](https://dashboard.render.com/) and create a **Web Service**. Use the GitHub repository `ianpgh/ShadyInc-Addons` and the `feature/shady-remote-publisher` branch. Connect GitHub if prompted, granting repository access only to this project. The service can be created before auth is configured. For a test deployment select **Free**, **Docker**, root directory `remote-publisher`, and one instance. Leave Docker command and Dockerfile path at their defaults. Disable automatic deploys if you want to deploy only reviewed commits. Render assigns a unique HTTPS URL. Free services sleep; persistent sessions are stored in PostgreSQL.
2. In [GitHub App settings](https://github.com/settings/apps/new), create a private GitHub App in your personal account, accessible **Only on this account**. Use the Render HTTPS origin as the homepage and set the callback URL to that origin plus `/oauth/callback`. Clear the Webhook **Active** checkbox. Leave device flow and install-time OAuth callbacks disabled. Keep expiring user tokens enabled.
3. Under repository permissions, set **Contents** to **Read and write** and leave **Metadata** at its required read-only setting. Leave all other permissions unset. Install the app on **only** `ianpgh/ShadyInc-Addons`. This is separate from Render’s GitHub integration.
4. In the GitHub App settings copy its **Client ID** and generate a **Client secret**. In Render's environment settings add `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, and `PUBLIC_ORIGIN` (exact assigned HTTPS origin with no suffix). Store the client secret only on the hosting provider. The app needs no PAT, webhook secret, or GitHub App private key.
5. Deploy and open the HTTPS service. Sign in as `ianpgh`, use **Refresh Repository**, then validate a candidate ZIP without publishing it. Check that an unrelated GitHub account has no publishing access. Keep production releases untouched until explicitly approved.
6. In Safari, use **Share → Add to Home Screen → Open as Web App → Add**. Open the new icon and sign in from the web app if Safari's session is separate.

Use one container replica and an HTTPS reverse proxy with request time and body limits. The proxy must preserve the request Origin and forward a Content-Length for uploads. Set DATABASE_URL to the pooled Neon PostgreSQL connection string and SESSION_ENCRYPTION_KEY to a securely generated Base64-encoded 32-byte key. Startup initializes the session table. A host restart retains encrypted sessions, but validation tickets expire; validate again before publishing. Sessions have a rolling 90-day cookie and database expiry; GitHub tokens renew automatically until revoked or refresh credentials expire. Do not rotate the encryption key without expecting existing sessions to become unreadable. Use the assigned service URL as the direct mobile app URL.

## Publishing and recovery

- Uploading and validating sends data only to the service. The queue stays in memory. Validated ZIPs are staged in bounded process memory (64 MiB total, 30-minute lifetime); publishing normally sends only a ticket. Expired or evicted ZIPs require revalidation and renewed confirmation. Background publish jobs are polled by their session-bound ticket; after a restart use verification before retrying. The server inspects the exact bytes again when you confirm publication. A compatible manual channel selection must agree with the TOC version.
- Each package is its own commit. Stable uses `latest.json`, Alpha uses `alpha.json`, and Beta uses `beta.json`. The ZIP keeps the desktop publisher's filename and checksum format. A failed package does not prevent other packages from being attempted.
- The server compares the live ref before commit and uses a non-force push. After an uncertain push, it checks GitHub before making one bounded retry. An identical publication is reused. A retry can fill in missing files or metadata when the reviewed channel and checksums allow it. A conflicting ZIP or a version retained by rollback requires a separate review.
- The queue automatically switches from **Publishing** to **Verifying**, even if the upload or response times out. It checks the ZIP checksum, channel metadata and catalog on GitHub, then checks GitHub Pages and the public download. **Successfully Published** means those checks passed; verified items leave the queue after three seconds. Failed and partial items remain available for verification or retry. **Partially Published** identifies an incomplete release or a public feed that still needs to catch up. **Confirmed Failure** means GitHub reported an absent release on repeated checks or exposed a conflict. An unavailable GitHub check stays in **Verifying**.
- Use **Verify Publication** to recheck a package or an active release from history. If verification reports missing files or metadata, validate the same ZIP and confirm publication to repair them. After reloading the page, select the same ZIP to check for an existing publication.
- History shows matching release commits with author/source and Eastern time. Restore an earlier version from the same channel and confirm explicitly. Rollback commits only the selected manifest, retains all ZIPs, and requires the reviewed head to remain current. Catalog descriptions and features remain as currently published.
- The remote service accepts addon ZIPs and Desktop Addon Manager update ZIPs with the existing manager manifest and executable layout.
- Sign-out deletes the server-side session. For emergency revocation, uninstall the GitHub App or revoke its authorization in GitHub, rotate the client secret if exposed, and stop or redeploy the service. Git history records successful mutations and the service emits structured operation logs. Host log retention is dependent on the selected plan.

## Local checks

Install Git, Python 3.10+ and Lua 5.1. Run `python3 tests.py` in this directory. If the compiler is installed at a different path, set `TEST_LUAC` to its absolute path. `node --check web/app.js` checks the client script. Read [AUDIT.md](AUDIT.md) for repository verification, test coverage and release gates.
